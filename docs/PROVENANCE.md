# Provenance of the page builder

The page builder was rebuilt on GrapesJS ([ADR 0022](adr/0022-grapesjs-page-builder.md)) using the legacy product's builder as the reference for behaviour. This file records what was read, what was reused and what was deliberately left behind, so that the origin of every adapted file can be audited.

**Rights.** The project owner provided the legacy front end for this work and confirmed that they hold the rights to use and publish it. The repository is public.

**Method.** The legacy sources were read, and the logic that mattered (component model, drop rules, block catalogue and default content, per-element settings, commands, style-manager sectors, visibility classes, outline colours, component-version reconciliation) was re-implemented against the npm package `grapesjs` with the user interface written from scratch (Radix and Tailwind). **No legacy file was copied, no stylesheet text or markup was pasted, and the vendored minified GrapesJS build was not used.** Each adapted file starts with a header comment pointing here.

**Not carried over, on purpose.** Credentials, API endpoints, hostnames, analytics identifiers, brand names and personal data of the legacy product (the scan of this repository's diff for them is part of the release checklist below); the form block's call to an external service (forms post to this app's own `/api/public/forms` endpoint); the legacy UI libraries (MUI, react-query v3, react-router v5) and its in-house UI kit, toast and publish/subscribe helpers; trusting HTML sent by the browser (the server now renders and sanitises, see [SECURITY.md](SECURITY.md#page-builder-and-published-pages)).

## Where each part came from

Legacy paths are relative to the front end's `src/Pages/Funnel/FunnelBuilder/` unless noted.

| Legacy source | What was taken | Where it lives now | What changed |
|---|---|---|---|
| `index.js` (editor configuration, devices, undo manager, layer, style and selector managers) | The shape of the configuration: canvas, desktop and mobile devices with their media widths, undo manager, managers rendered by the host application | `web/src/builder/editor/createEditor.ts` | Tablet added; every GrapesJS panel disabled; telemetry and the icon font CDN switched off; frame CSP; the page root is the canvas body |
| `Blocks/{Section,Row,Text,Media,Form,Checkout,Countdown,Custom}` | Block categories and elements (section widths, rows of one to six columns, heading, sub-heading, paragraph, bullet list, link, image, video, form, checkout with order bump and one-click upsell, countdown, FAQ, divider, progress bar, popup, custom code) and their default content | `web/src/builder/editor/blocks.ts`, `server/src/pagemodel/shared/build.ts` | Default markup is generated by one DSL that templates also use, so a dropped block equals a template's block; more than twenty blocks added (heroes, pricing, testimonials, cards, navbar, footer, tabs) |
| The component definitions in `index.js` and the `gjs-element`, droppable and draggable constraints | The Section > Row > Column > element model and its constraints (sections on the page only, rows in sections, columns in rows) | `web/src/builder/editor/types.ts`, `editor/rules.ts` | One pure function (`canDrop`) replaces selector strings on every component; dynamic components keep behaviour in typed props, not DOM attributes or embedded frames |
| `Settings/` (ButtonSettings and OnClickSettings, FormSettings, CountdownSettings, CheckoutSettings, FaqSettings, ImageSettings, VideoSettings, PopupSetting, ProgressBarSettings) | The set of per-element settings and what each one edits (button actions, form fields and consent, evergreen and fixed timers, product, bump and upsell, questions, image source and alt, video URL, popup target, progress value) | `web/src/builder/panels/traits.tsx`, `server/src/pagemodel/shared/props.ts` | Each setting is a React editor for one typed trait, validated by the zod schema the server applies; about sixty legacy setting types were not needed because styling is one generic Style panel |
| `commands.js`, `Constants/Funnels/builderCommands.ts` | The command set: undo, redo, device switch, preview, history, page settings, save, popup; move up and move down | `web/src/builder/editor/commands.ts` | GrapesJS commands plus keymaps; the per-element "add row" and "add element" buttons are replaced by real drag and drop, the floating toolbar and keyboard shortcuts |
| `styles/`, `public/builderStyles.css` | Editor-only appearance: selection and outline colours (sections green, rows and columns blue, elements orange), dashed empty containers, the `show-none`, `show-desktop-only` and `show-mobile-only` classes | `web/src/builder/editor/canvasCss.ts`, `server/src/pagemodel/shared/css.ts` | Rewritten as one stylesheet; the visibility classes now live in the published page CSS and are set in Settings, Advanced |
| Style manager sectors (typography, background, border, radius, shadow, spacing, size, position, visibility per device) | The grouping and order of style sections | `web/src/builder/panels/StylePanel.tsx`, `styleControls.tsx` | Written for the new design system, with a target switch (this element or a class), states and a box-model grid |
| The layer manager panel | Visibility toggle, nested list, drag to reorder | `web/src/builder/panels/LayersPanel.tsx` | Built on the GrapesJS Layers API; adds lock, keyboard moves and the canvas's drop rules |
| The top bar | Back, page dropdown, device switch, undo, redo, preview, save | `web/src/builder/panels/TopBar.tsx` | Adds history, page settings, shortcuts, publish and a compact layout below 640 px |
| `Utils/reconciliationUtility.js`, `Constants/Funnels/componentVersions.json` | The idea of stamping components with a shape version and migrating old ones when a page is opened | `COMPONENT_VERSION`, `COMPONENT_MIGRATIONS` and `reconcileNode` in `server/src/pagemodel/shared/clean.ts` | Runs in the shared module on the server and in the editor; no migration is registered yet |
| `Utils/generateHTML.js`, `Utils/handlers.js` (save and export clean-up) | The list of what the editor adds to the page that must not be published (`gjs-*` classes, `data-gjs-*` attributes, `contenteditable`, outlines, the editor script) | `server/src/pagemodel/render.ts`, `shared/clean.ts` | Removed by construction: the server renders from the cleaned project and never from editor DOM; a browser test asserts none of them is in the published page |

Files with a header comment: `web/src/builder/editor/{createEditor,blocks,types,rules,commands,canvasCss}.ts`, `web/src/builder/panels/{TopBar,StylePanel,LayersPanel,traits}.tsx`. `BuilderApp.tsx` and the other panels, the whole server-side page model (`server/src/pagemodel/`), the converter, the assets feature, the design system (`web/src/ui/`) and the seeded templates are new work and not derived from the legacy builder; the templates reproduce the structure of the templates already shipped with this app, not of the legacy product's.

## Release checklist for this directory

* The added lines of `git diff 39a2a0f..HEAD` (everything the builder work added; lock file, generated OpenAPI and screenshots excluded) were scanned on 2026-10-20 for URLs and hosts, the legacy brand names, cloud and payment key shapes, analytics identifiers (`G-`, `UA-`, `gtm-`), connection strings and literal passwords. Hosts found: `example.com`, `example.test` and similar placeholders, `evil.example` (hostile payloads in tests), YouTube and Vimeo (the video allow-list), Google Fonts, `w3.org` (the SVG namespace), `json-schema.org`, `localhost` and `127.0.0.1`. No legacy brand name, key, token or analytics id was found. The only literal password is the demo account's, which `src/seed.ts` already documented. Repeat the scan before every release with the same command.
* `npm run docs:check` and the tests listed in [TESTING.md](TESTING.md) green.
